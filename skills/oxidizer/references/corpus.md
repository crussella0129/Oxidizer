# The corpus: building, refreshing, and what is in it

Read this when the corpus is missing, stale, or you need to change what is
mirrored.

## Building

```bash
rustup component add rust-docs                      # ~750MB, one time
python3 skills/oxidizer/scripts/mirror.py --online  # ~30s
```

The offline sources come from `$(rustc --print sysroot)/share/doc/rust/html`.
`--online` additionally fetches the two Brown University sources, which have no
offline equivalent. Skipping `--online` yields a fully functional corpus without
them.

Output goes to `corpus/` at the repository root, or `$OXIDIZER_CORPUS` if set.
It is generated and gitignored — rebuild it, do not commit it.

## Why the local toolchain rather than doc.rust-lang.org

`doc.rust-lang.org` always serves stable-latest. A project pinned to an older
toolchain will disagree with it, silently, in exactly the cases where the user
most needs a correct answer — a method that is not stable yet, a lint that was
renamed, an edition default that changed. Mirroring from the installed toolchain
makes the corpus correct by construction for the compiler that will actually run
the code.

`oxidize manifest` compares the corpus's recorded `rustc --version` against the
current one and reports `STALE` when they differ.

## Selecting sources

```bash
python3 scripts/mirror.py --include core,alloc      # no_std work
python3 scripts/mirror.py --include unstable-book   # nightly features
python3 scripts/mirror.py --only std,lints          # rebuild a subset
python3 scripts/mirror.py --check                   # freshness, writes nothing
```

`--only` merges into the existing manifest rather than replacing it, so
rebuilding one source does not orphan the others.

Defaults on: `book`, `rust-by-example`, `reference`, `nomicon`, `error-index`,
`std`, `cargo`, `clippy`, `edition-guide`, `style-guide`, plus `lints`.
Off by default: `core`, `alloc`, `embedded-book`, `unstable-book` — large, and
std re-exports most of what `core` and `alloc` provide.

## How documents are produced

mdBook pages (`book`, `rust-by-example`, `reference`, `nomicon`, `error-index`,
`cargo`, `edition-guide`, `style-guide`) keep their content in `<main>`; rustdoc
pages (`std`) use `<section id="main-content">` and carry per-member signatures
in `<section id="method.*">` anchors. Both convert to markdown with a stdlib-only
parser — no pip install stands between a user and a working corpus.

For rustdoc pages the extractor also emits a **Members** section: every method's
signature plus its doc block, each as its own heading. That is what lets
`oxidize api Vec::retain` return ~90 tokens instead of the 96,000 the full `Vec`
page costs.

Redirect shims and retired-edition notices are dropped at mirror time. They rank
well on title match while containing no answer, and filtering them at query time
would mean carrying ~750 dead documents.

## The lint index is special

rustup does **not** ship clippy's lint list offline: the clippy book fetches it
with JavaScript at page load, so `share/doc/rust/html/clippy` contains only
clippy's own development documentation. The lint data is instead generated by
running `clippy-driver -W help` (falling back to `rustc -W help`), which
enumerates every lint the installed toolchain knows along with its default
level. This is offline, exactly version-matched, and covers rustc and clippy
lints together — 1,056 entries on a current stable toolchain.

The trade-off: one-line descriptions rather than the full write-ups on
rust-lang.github.io. Enough to identify and act on a lint; for rationale, follow
up in the Book.

## Known gaps

- **crates.io / lib.rs.** Not mirrored. `lib.rs`, named in the project brief, is
  blocked by this environment's egress policy (HTTP 403), and no third-party
  crate documentation is included.
- **Full-text search.** The index carries titles, headings, summaries, member
  names, and the 80 most distinctive body terms per document — not complete
  bodies. Distinctive vocabulary is findable; an arbitrary phrase buried in
  prose may not be. `show` the document and read it when you need certainty.
- **Translated pages.** Rust By Example ships several languages and they are all
  mirrored, so a search can surface a Spanish or Japanese hit. Harmless, but
  check the title before quoting.

## Size

5,263 documents and ~8.1M tokens for the default set plus `--online`: 39.6 MiB
of markdown plus 7.7 MiB of `INDEX.json`, distilled from 750 MiB of HTML. (`du`
reports 56 MiB, counting allocated blocks across 5,263 small files.)

That is small enough to keep several corpora around for different toolchains if
you need to. It is dwarfed by any Rust `target/` directory — see
`disk-hygiene.md`, and `oxidize disk` for the current numbers.
